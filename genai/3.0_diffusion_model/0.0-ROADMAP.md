# Diffusion and Flow Matching Lessons

The foundation sequence follows reading-guide units **4.4 DDPM/DDIM**, **4.5
Score-SDE and probability-flow ODE**, and **4.6 Flow Matching** in
`4-diffusion-and-flow-foundations` (alignment checked on 2026-09-10). Learn a
local prediction field, then freeze it and compare complete generation
procedures. Each training script keeps its target, loss, optimizer update,
and EMA update visible.

## 1. Learning order

| Guide | Lesson | Algorithmic increment |
|---|---|---|
| 4.4 | [1.0 DDPM](1.0_ddpm.py) | Closed-form Gaussian corruption, analytic posterior, fixed variance, epsilon MSE, full ancestral generation |
| 4.4 | [1.1 DDIM sampling](1.1_ddim_sampling.py) | Freeze DDPM; compare the adjacent chain with DDIM subsequences and eta |
| 4.5 | [2.0 Score-SDE](2.0_score_sde.py) | Continuous denoising score matching; VP baseline with VE/sub-VP alternatives |
| 4.5 | [2.1 SDE/ODE sampling](2.1_sde_ode_sampling.py) | Freeze the score; compare reverse-SDE Euler-Maruyama with Euler/Heun PF-ODE |
| 4.6 | [3.0 Conditional Flow Matching](3.0_flow_matching.py) | Independent endpoints, conditional Gaussian paths, direct velocity MSE, full ODE generation |
| 4.6 | [3.1 Flow sampling](3.1_flow_sampling.py) | Freeze the velocity; compare Euler, midpoint, and Heun under fixed noise and quality protocols |

The linear independent-endpoint CFM baseline is also the starting objective
of Rectified Flow. It does not need a second identical training script.
Reflow, optimal-transport coupling, interval maps, MeanFlow, and distillation
are beyond the current foundation units. CNF describes the ODE model family;
CFM supplies its simulation-free training objective. Likelihood estimation
with divergence/Hutchinson probes is not part of these lessons, and velocity
MSE is not a likelihood or a density-consistency certificate.

The earlier Improved DDPM, EDM, DPM-Solver comparison, KL autoencoder, and LDM
lessons remain runnable under [extensions/](extensions/README.md), outside
the foundation order. Their shared modules and output/checkpoint locations
remain available. The DDIM entry point moved from `1.2_ddim_sampling.py` to
`1.1_ddim_sampling.py`; extension path changes are listed in its README.

## 2. Three different prediction contracts

| Model | Training direction and target | Generation |
|---|---|---|
| DDPM | Data to noise; regress epsilon (optional x0, diffusion-v, or score) | Decreasing discrete indices; full DDPM chain or DDIM subsequence |
| Score-SDE | Data at t=0, noise at t=1; regress conditional score `-epsilon/sigma(t)` with sigma-squared weighting | Integrate 1 to a positive delta, optionally followed by a separate Tweedie denoise |
| CFM | Noise at t=0, data at t=1; regress `d(x_t)/dt` | Integrate 0 to 1 directly, without endpoint denoising |

DDPM's Python index 0 denotes the first **noisy** state; clean data uses the
sampler's terminal index -1. DDIM reconstructs x0, its consistent noise
direction, and an eta-controlled random component. If x0 is clipped, epsilon
is recomputed. Skipping adjacent DDPM transitions alone is not DDIM.

Score-SDE samples continuous time uniformly on `[delta, 1)`. The network sees
only the perturbed image and time. Its loss is
`mean((sigma(t) * score_theta + epsilon)^2)`, the stable form of weighted
conditional score matching. Reverse SDE uses negative dt with Brownian
standard deviation proportional to `sqrt(-dt)` on every interval. PF-ODE
halves the score correction and omits Brownian noise. True fields share
time marginals, not individual trajectories; learned finite-step results
also include model, prior, discretization, and endpoint errors.

For CFM, independently draw Gaussian `noise` and real `data`. A linear path
uses `state=(1-t)*noise+t*data` and `target=data-noise`. The optional
trigonometric path uses `alpha=sin(pi*t/2)`, `sigma=cos(pi*t/2)` and their
analytic derivatives in `target=alpha_dot*data+sigma_dot*noise`. Both have
the same exact mathematical endpoints and finite direct-velocity targets.
Time is uniform on `[0,1)` and loss weight is one. Targets and states are
detached; no ODE is solved inside the training loss.

Conditional targets depend on sampled endpoints; the network only receives
`(state,time)`. Squared regression learns their posterior mean, the marginal
velocity. Conditional straight lines therefore do not imply straight learned
trajectories. CFM and marginal FM have the same population gradients under
the same time measure and time-only weighting, while their losses can differ
by a parameter-independent residual variance.

The [flow module](../../dl_utils/diffusion/flow_matching.py) includes the
score-to-velocity identity for the **same Gaussian path at interior times**.
It is not an adapter for an unrelated DDPM schedule. Diffusion-v is a rotated
data/noise target, not this general `dx/dt`. The common time embedding scale
of 1000 changes only the network input; physical dt and velocity keep their
original units.

## 3. Data and model scale

All image lessons use **128x128 RGB by default**. Pixel training accepts
`--image-size 256`; 128 is appropriate for aligned CelebA's native 178px face
crop. Enlarging that crop to 256 does not add detail. Comparison scripts use
the checkpoint's RGB resolution.

Prepare the aligned [CelebA dataset](https://mmlab.ie.cuhk.edu.hk/projects/CelebA.html)
with the existing [preparation tools](../../tool_scripts/README.md), then use
`data/celeba` or `--data-dir`. The [loader](../../dl_utils/data/celeba.py) uses
the full official splits: 162,770 train, 19,867 validation, and 19,962 test.
Preprocessing is a 178px center crop, bilinear resize, and normalization to
`[-1,1]`. Only training uses random horizontal flips. No lesson downloads data.

The shared U-Net defaults to channels `(64,128,256,384)`, about **31.1M
parameters**, with attention at the 16x16 bottleneck. CFM reuses this backbone
with a three-channel velocity head. Batch size defaults to 8. Training uses
one device, full precision, AdamW, and EMA. CFM records the gradient norm
before clipping to `--max-grad-norm` (default 1); DDPM and Score-SDE record
the unmodified norm. Non-finite gradients stop an update before optimizer/EMA.

## 4. Quality monitoring from DDPM onward

All generative training lessons evaluate EMA every ten epochs and at the
final epoch, unless `--eval-every 0` is selected. DDPM defaults to full
ancestral evaluation; `--eval-sampler ddim --ddim-steps 50` changes that
protocol and reduces its cost. Score-SDE defaults to PF-ODE/Heun with 250
intervals and endpoint denoising; CFM defaults to Heun with 50 intervals.

The shared [quality monitor](../../dl_utils/diffusion/quality.py) records:

| Metric | Meaning | Protocol |
|---|---|---|
| `torchvision_fid` | Lower distribution distance is better | Full 2048D torchvision Inception pool features, no random projection |
| `torchvision_kid_mean` | Lower distribution distance is better | Unbiased polynomial MMD; 20 subsets of at most 512 images |
| `feature_precision` | Generated-feature fidelity | k-NN manifold estimate, k=3 |
| `feature_recall` | Real-feature coverage | k-NN manifold estimate, k=3 |
| `nfe_per_image`, sampling time | Actual network cost and latency | Forward hooks count model evaluations, including endpoint denoising |

These are within-project torchvision measurements, not published TF/clean-FID
scores. ImageNet weights may download at the first real evaluation. The
default is 2,048 fixed validation images and equally many freely generated
images. `--eval-examples`, `--eval-batch-size`, and `--eval-seed` define the
protocol; use a larger fixed count such as 10,000 for final comparisons.
Small-sample FID is noisy and may use rank-deficient covariance estimates.
KID can be negative; subset standard deviation is not a confidence interval.
Inspect the saved grids alongside every metric. ImageNet Inception Score is
omitted for this faces-only task.

With K intervals, reverse SDE and PF-Euler use K calls, PF-Heun uses 2K;
Score-SDE's optional final denoise adds one. CFM Euler uses K calls and
midpoint/Heun use 2K, with no extra terminal call. The comparison scripts
allow both equal-interval and equal-NFE comparisons. Initial noise stays
fixed between solvers; Brownian transition noise uses a separate stream.
CFM integrates raw states without clipping and clamps only terminal RGB
for evaluation. Quality records identify the grid, time scale, endpoint
policy, model state, sample count, seeds, and preprocessing. Sampling time
excludes feature extraction; LDM extension time includes decoding.

Training writes `latest.pth` and `training.jsonl`; evaluation adds
`quality.jsonl` and grids. Loss records include the whole-split mean and
three noise/time bins. CFM additionally records velocity RMS and current/EMA
probes at t=0, 0.5, and 1. Those probes use the same last training minibatch
and fixed probe noise for both models, in eval mode; their minibatch can
change between epochs. They diagnose scales and EMA lag, while held-out
free-generation metrics measure quality. Evaluation preserves training RNG.

## 5. Entry points and resume

These are future training/evaluation commands, not actions performed by this
refactor. Run them from the repository's locked uv environment:

```bash
uv run --locked --no-sync python genai/3.0_diffusion_model/1.0_ddpm.py
uv run --locked --no-sync python genai/3.0_diffusion_model/1.1_ddim_sampling.py
uv run --locked --no-sync python genai/3.0_diffusion_model/2.0_score_sde.py
uv run --locked --no-sync python genai/3.0_diffusion_model/2.1_sde_ode_sampling.py
uv run --locked --no-sync python genai/3.0_diffusion_model/3.0_flow_matching.py
uv run --locked --no-sync python genai/3.0_diffusion_model/3.1_flow_sampling.py
```

Use `2.1_sde_ode_sampling.py --no-final-denoise` to isolate the endpoint
correction, keeping it identical across the compared methods. For a separate
CFM path experiment, train with `--path trigonometric --output-dir
output/diffusion/cfm_trigonometric`, then pass that checkpoint to 3.1. Changing
the path changes the training problem; it is not a sampler-only toggle.

Fresh runs initialize output with `reset_dir`. Resumed runs use `--resume-from`
and preserve their output history. Checkpoints store model, EMA, optimizer,
PyTorch RNG, data preprocessing, and prediction/path metadata. CFM also fixes
coupling, time direction/sampling/embedding, loss weighting, condition interface,
and evaluation solver protocol. Resume is at an epoch boundary; persistent
worker augmentation RNG is not serialized, so replay is not bit-identical.
Importing a lesson or running `--help` performs no training or data download.
