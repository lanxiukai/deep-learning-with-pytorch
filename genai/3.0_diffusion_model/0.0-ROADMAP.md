# Diffusion Model Lessons

The main line follows the discrete diffusion and continuous diffusion/solver
units (4.4 and 4.4a) of the reading guide: learn a denoiser first, then freeze it
and change the reverse update. Each training script keeps its objective and
optimization loop visible. KL autoencoding and latent diffusion remain a later
extension, after the pixel-space foundations.

## 1. Learning order

| Lesson | Algorithmic increment | Training or generation |
|---|---|---|
| [1.0 DDPM](1.0_ddpm.py) | Gaussian forward kernel, analytic posterior, epsilon MSE; optional x0/v/score conversions | Train fixed posterior variance; monitor EMA generation |
| [1.1 Improved DDPM](1.1_improved_ddpm.py) | Cosine schedule, separate epsilon/variance heads, hybrid MSE + VLB | Train a distinct model; ancestral sampling uses learned variance |
| [1.2 DDIM](1.2_ddim_sampling.py) | Reuse either discrete model; separate predicted x0, noise direction, and eta | Compare the full DDPM chain with several DDIM subsequences |
| [2.0 Score-SDE](2.0_score_sde.py) | Continuous score matching on VP, VE, or sub-VP; optional discrete VE levels for NCSN | Train the score; reverse SDE, PC, PF-ODE, or annealed Langevin generation |
| [2.1 EDM](2.1_edm.py) | Input/output/skip/noise preconditioning, log-normal training noise, weighted denoising | Train its own denoiser; Euler/Heun on a rho-shaped sigma grid |
| [2.2 Solver comparison](2.2_solver_comparison.py) | Euler, Heun, DPM-Solver-1/2M, DPM-Solver++-2M | Freeze one checkpoint; compare quality, actual NFE, and time |
| [3.0 KL autoencoder](3.0_kl_autoencoder.py) | Pixel/perceptual/adversarial reconstruction with weak spatial Gaussian KL | Train an f=8 first stage and estimate one latent scale |
| [3.1 Latent diffusion](3.1_latent_diffusion.py) | Apply DDPM to frozen scaled latents; optional Smiling conditioning/CFG | Train a latent denoiser; decode samples and evaluate RGB quality |

`1.1_ddpm_sampling.py` is now `1.2_ddim_sampling.py`; `4.0_edm.py` is now
`2.1_edm.py`. Training and frozen solver comparison have separate entry points.
The earlier 32px CIFAR-10 checkpoints are incompatible with this series's new
data, model, and first-stage contracts. The external reading guide's older
code-location prose may still use the previous names.

## 2. Shared data and model scale

Every lesson trains on or generates **128x128 RGB images by default**. Pixel
lessons accept `--image-size 256`, but 128 is the appropriate default for
aligned CelebA: its 178px face crop contains enough native detail for 128px;
resizing that crop to 256 does not add information. Existing CIFAR-10 images
are not enlarged to meet the resolution target.

Use the locally prepared aligned [CelebA dataset](https://mmlab.ie.cuhk.edu.hk/projects/CelebA.html)
at `data/celeba`, or pass `--data-dir`. The existing
[preparation tools](../../tool_scripts/README.md) and
[CelebA loader](../../dl_utils/data/celeba.py) supply:

- 162,770 training images; 19,867 validation images; 19,962 test images.
- A 178px center crop, bilinear resize, and RGB normalization to `[-1, 1]`.
- Random horizontal flips only for training. Validation and latent-scale
  estimation use deterministic preprocessing. No lesson downloads data.

Pixel denoisers default to channels `(64, 128, 256, 384)`, about **31.1M
parameters**, with attention at the 16x16 bottleneck. Batch size defaults to 8;
adjust it to available memory. Training is ordinary full precision, one device,
AdamW, and EMA, without compilation or a distributed training layer. Equal
training budgets must use the same batch size, image count, and optimizer
updates, not merely the same epoch count.

The KL first stage has about 4.5M parameters and downsamples by eight. Thus
128px images become `4x16x16` latents; the roughly 31.7M-parameter latent U-Net
operates there, and decoding restores 128px RGB. The first-stage configuration,
latent scale, and saved checkpoint identity must match. Its weights stay
frozen during LDM training. Latents are never clipped to the pixel range.
LDM and comparison scripts take their RGB resolution from the loaded
checkpoints.

## 3. Quality monitoring from DDPM onward

All generative training lessons evaluate EMA weights every 10 epochs and at
the final epoch, unless `--eval-every 0` is selected. DDPM/Improved DDPM default
to their full ancestral samplers so the learned variance is exercised; use
`--eval-sampler ddim --ddim-steps 50` for a cheaper, explicitly different
monitor. A full-chain evaluation can take substantially longer than an epoch.
Score-SDE defaults to PF-ODE/Heun, EDM to Heun, and LDM to DDIM.

The shared [quality module](../../dl_utils/diffusion/quality.py) records:

| Metric | Interpretation | Protocol |
|---|---|---|
| `torchvision_fid` | Lower is better; Gaussian feature-distribution distance | Full 2048D Inception pool features, no random projection |
| `torchvision_kid_mean` | Lower is better; polynomial-kernel distribution distance | Unbiased estimate, 20 random subsets of at most 512 images |
| `feature_precision` | Higher indicates better generated-feature fidelity | k-NN manifold precision, k=3 |
| `feature_recall` | Higher indicates better real-feature coverage | k-NN manifold recall, k=3 |

These are **within-project torchvision metrics**, not interchangeable with
published TensorFlow/clean-FID scores. They reuse the existing Inception
extractor, Fréchet calculation, and polynomial MMD. The extractor now also
supports `projection_dim=None` for full features; its existing projected mode
is preserved. ImageNet weights may download at the first real evaluation.

The default reference is 2,048 fixed validation images, with the same number
of freely generated images. `--eval-examples`, `--eval-batch-size`, and
`--eval-seed` control the protocol. Small reference sets make FID noisy and
rank-deficient; use a larger fixed count, such as 10,000, for a final comparison.
KID can be slightly negative; its subset standard deviation is not a confidence
interval. Precision/recall depends on sample count and k. No single number
replaces inspecting saved sample grids. Inception Score is omitted because
ImageNet class confidence is poorly matched to a faces-only task.

Generative training runs save `latest.pth` and `training.jsonl`; evaluation adds
`quality.jsonl` and sample grids. Quality records include preprocessing, seeds, checkpoint
state, sampler/grid, sample count, actual denoiser calls, NFE per image, and
sampling latency. Endpoint denoising and both CFG branches count toward NFE.
Latency includes latent decoding for LDM, but excludes feature extraction and
metric computation. Validation RNG use does not advance the training RNG.
The comparison scripts keep initial noise separate from transition noise so
stochastic and deterministic samplers start from the same images.

The autoencoder is a reconstruction stage, so it reports L1, PSNR, SSIM,
perceptual distance, and KL; its standard-normal decode is an interface
diagnostic. Free-generation FID/KID/precision/recall resumes after training the
latent prior in 3.1. Optional CFG uses the training Smiling label prior and
reports its guidance strength with the RGB metrics.

## 4. Algorithm boundaries

- Improved DDPM uses the raw variance-head mapping `r=(v+1)/2`, without a
  sigmoid/clamp. The hybrid objective is `MSE + lambda*T*VLB_t`, with a detached
  mean, a finite first-step variance, and an 8-bit discretized Gaussian endpoint
  likelihood. Resized training pixels are quantized to that bin grid. The
  logged VLB estimate excludes the constant prior KL and is **not** a full
  likelihood. Run both models with linear scheduling to isolate variance
  learning, then compare cosine separately. Pure-VLB importance sampling is
  left as a separate extension.
- DDIM ignores learned variance and uses its own eta convention. Clipping x0
  also recomputes epsilon, keeping the direction consistent. DDPM cannot skip
  adjacent transitions without deriving a new posterior.
- VP, VE, and sub-VP share weighted score supervision but have different
  perturbation variances and SDE diffusion coefficients. Reverse SDE includes
  Brownian noise on every interval; final Tweedie denoising is a separate call.
  PC adds Langevin corrections with the declared rule
  `eta(t)=langevin_step_size*sigma(t)^2`. Discrete VE training plus annealed
  Langevin provides an NCSN lesson; this is not an exact NCSN architecture
  reproduction or an adaptive-SNR corrector.
- EDM training noise and sampling endpoints are independent. Heun uses a
  second network call except on the final interval to zero, which uses Euler.
- The VP solver comparison uses increasing `lambda=log(alpha/sigma)`.
  Discrete models use piecewise-linear log-alpha interpolation and fractional
  U-Net step indices; continuous VP models invert their continuous path.
  DPM-Solver predicts epsilon; DPM-Solver++ converts to x0 and uses different
  coefficients. The 2M methods reuse the preceding prediction after a
  first-order start. Third order, adaptive stepping, and distillation are
  omitted. Euler/Heun/1/2M use the same finite endpoint and an additional final
  x0 prediction. Intervals and NFE are separate quantities.

## 5. Entry points

Run from the repository's locked uv environment. The following are future
training/evaluation commands; the refactor itself does not run training:

```bash
uv run --locked --no-sync python genai/3.0_diffusion_model/1.0_ddpm.py
uv run --locked --no-sync python genai/3.0_diffusion_model/1.1_improved_ddpm.py
uv run --locked --no-sync python genai/3.0_diffusion_model/1.2_ddim_sampling.py --sampler both
uv run --locked --no-sync python genai/3.0_diffusion_model/2.0_score_sde.py
uv run --locked --no-sync python genai/3.0_diffusion_model/2.1_edm.py
uv run --locked --no-sync python genai/3.0_diffusion_model/2.2_solver_comparison.py \
  --checkpoint output/diffusion/ddpm/latest.pth --steps 25 50
uv run --locked --no-sync python genai/3.0_diffusion_model/2.2_solver_comparison.py \
  --checkpoint output/diffusion/edm/latest.pth --solvers euler heun
uv run --locked --no-sync python genai/3.0_diffusion_model/3.0_kl_autoencoder.py
uv run --locked --no-sync python genai/3.0_diffusion_model/3.1_latent_diffusion.py
```

For the discrete-score branch, use `2.0_score_sde.py --sde ve --noise-levels 64
--eval-sampler annealed_langevin --corrector-steps 10` and a distinct
`--output-dir`. Compare the same saved VE model with
`2.2_solver_comparison.py --solvers annealed_langevin --steps 64
--corrector-steps 10`. To sample an LDM checkpoint, use
`3.1_latent_diffusion.py --mode sample` with its matching
`--autoencoder-checkpoint`.

Fresh runs initialize output directories using `reset_dir`; resumed diffusion
runs preserve their output directory and restore model, EMA, optimizer, and
PyTorch RNG state through `--resume-from`. Directory resets never belong in a
dataset-loading helper. There is no automatic training launch when importing
a lesson or running `--help`.
Resume is at an epoch boundary; persistent data-loader worker RNG states are
not serialized, so it does not promise a bit-identical replay of augmentation.

checkpoints, and small loss records; objectives and optimization stay in the

[improved_ddpm.py](../../dl_utils/diffusion/improved_ddpm.py),

[training/optimization.py](../../dl_utils/training/optimization.py).
