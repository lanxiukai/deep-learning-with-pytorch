# Diffusion and Flow: the A/B Teaching Curriculum

These lessons implement the three foundation units and eight modern visual
units from reading-guide 4.2, with the mechanisms in 4.3a through 4.5c. The
common task is Food-101 at **256 x 256 RGB**, with **101 semantic classes**.
Each training entry exposes its target, loss and parameter updates. Independent
evaluation entries load frozen checkpoints. There is no `extensions/` tier.

## 1. Common data and representation

Run from the repository root in the locked project environment:

```bash
uv sync --locked --extra diffusion
uv run --locked --no-sync python genai/3.0_diffusion_model/0.1_prepare_data.py --download
```

`--data-dir` defaults to `data/food101`. The official archive lives inside
`food-101/`; `diffusion_manifest.json` contains relative image IDs and the
same alphabetical class mapping for every lesson. Downloading and manifest
preparation are explicit, separate operations from training.

| Split | Images per class | Total | Use |
|---|---:|---:|---|
| Train | 700 | 70,700 | Generator, codec, classifier and regression training |
| Validation | 50 | 5,050 | Checkpoint/configuration/guidance selection |
| Official test | 250 | 25,250 | Final evaluation only |

The validation IDs are selected deterministically from the official 750
training images per class, using split seed 42. No generator sees validation
or test images as training examples. Unconditional models use the same image
IDs and ignore labels. Food-101's training labels contain noise; a category
classifier is an imperfect evaluator, not ground truth for generated images.

Images use bicubic short-edge resize, center crop, RGB conversion and `[-1,1]`.
Only training adds horizontal flips. SR3 derives its 128px observation **after**
the shared geometry, with antialiased bicubic downsampling. Its output and
high-resolution target remain 256px. For a category cascade, train the same
conditional DDPM entry at 128px on the same manifest; this is a separate
checkpoint, not a resized 256px model.

The independently implemented KL codec compresses by eight to `4x32x32`.
It uses L1, learned LPIPS, weak KL and a delayed reconstruction PatchGAN.
After each epoch, the saved EMA codec's exact posterior second moments are
estimated on a fixed, unaugmented **training** subset. Their inverse RMS gives
one scalar latent scale. LDM, DiT, SiT and iMF freeze that codec and scale,
encode online with posterior sampling, and decode only after inverse scaling.
Continuous latents are never clipped to a pixel range. Checkpoints record the
exact codec checkpoint ID; replacing the codec requires retraining downstream
models. Preserve the selected codec checkpoint before continuing codec training.

There are **11 model units**, not 11 training runs. CFG, the KL codec, the two
classifiers and the SR regression control are necessary training stages.
REPA and other mechanisms need real matched retraining. The clean evaluator
and VP guidance classifier have independent parameters and training objectives.

DDPM and CFM have unconditional foundation baselines. VP learns an unconditional
score, then uses its separately trained noisy classifier for class guidance.
LDM/EDM/DiT/SiT/CD/DMD2/iMF train actual category-conditioned generators.
Original SR3 receives only the low-resolution image; labels enter the later
CDM variant and the upstream category generator.

## 3. Running and comparing the lessons

All commands below use relative paths from the repository root. Set
`DL_OUTPUT_ROOT` or pass `--output-dir` to use a cloud volume. Fresh runs require
an empty output directory. Resume explicitly with `--resume-from latest.pth`;
no training script clears previous experiments. The defaults are a teaching
starting configuration, not claimed converged hyperparameters.

```bash
uv run --locked --no-sync python genai/3.0_diffusion_model/1.0_ddpm.py --precision bf16
uv run --locked --no-sync python genai/3.0_diffusion_model/2.0_class_conditional_ddpm.py --precision bf16
uv run --locked --no-sync python genai/3.0_diffusion_model/0.2_class_evaluator.py
uv run --locked --no-sync python genai/3.0_diffusion_model/0.3_class_evaluator_evaluation.py --split validation
uv run --locked --no-sync python genai/3.0_diffusion_model/2.1_class_conditional_ddpm_evaluation.py \
  --class-evaluator output/diffusion/class_evaluator/latest.pth \
  --split validation --examples 5050 --solvers ddim --steps 25 50 --guidance 1 2 4
```

Use validation to choose configurations; then repeat the chosen setting with
`--split test` and the default 25,250 samples. Conditional evaluation samples
250 images per category. To inspect images without downloading metric weights,
use `--preview-only`; that mode makes no quality measurement.

```bash
uv run --locked --no-sync python genai/3.0_diffusion_model/5.0_kl_autoencoder.py --precision bf16
uv run --locked --no-sync python genai/3.0_diffusion_model/5.2_latent_diffusion.py \
  --autoencoder-checkpoint output/diffusion/kl_autoencoder/latest.pth --precision bf16
uv run --locked --no-sync python genai/3.0_diffusion_model/7.0_dit.py \
  --autoencoder-checkpoint output/diffusion/kl_autoencoder/latest.pth --precision bf16
uv run --locked --no-sync python genai/3.0_diffusion_model/8.0_sit.py \
  --autoencoder-checkpoint output/diffusion/kl_autoencoder/latest.pth --precision bf16
uv run --locked --no-sync python genai/3.0_diffusion_model/8.2_sit_repa.py \
  --autoencoder-checkpoint output/diffusion/kl_autoencoder/latest.pth --precision bf16
```

The same codec argument applies to iMF. Its initial configuration is FP32 for
JVP/gradient validation; BF16 is an explicit experiment. REPA uses a frozen
DINOv2 ViT-S/14 semantic teacher and a trainable projector. LPIPS, DINOv2 and
Clean-FID download their public pretrained weights when first needed. These
are declared external representation/evaluation resources, not extra Food-101
training samples. There is no random-feature substitution in real training.

```bash
uv run --locked --no-sync python genai/3.0_diffusion_model/6.0_edm.py --precision bf16
uv run --locked --no-sync python genai/3.0_diffusion_model/10.0_consistency_distillation.py \
  --teacher-checkpoint output/diffusion/edm/latest.pth --precision bf16
uv run --locked --no-sync python genai/3.0_diffusion_model/11.0_dmd2.py \
  --teacher-checkpoint output/diffusion/edm/latest.pth --student-steps 1 --precision bf16
```

Evaluate the EDM teacher's multi-step quality, category compliance and coverage
before distillation. Train a four-step DMD2 student in another output directory;
its inference grid is part of its training contract. CD and iMF support the
specified one/two/four-step evaluation on the same trained mapping. Run the
teacher's own evaluator with comparable network-evaluation budgets as the
teacher-directly-reduced baseline. Store teacher training and student training
records together when judging total cost.

### Required controlled increments

- **LDM:** `--unconditional` trains a separate baseline. The category model uses
  one-token cross-attention at the bottleneck. One key means softmax is exactly
  one: this teaches the category interface, not multi-token text selection.
- **DiT:** compare the baseline, `--rope`, `--qk-norm`, and both switches in
  separate output directories with the same data/codec/budget. Learned variance
  uses a continuous Gaussian latent endpoint, stopped epsilon in the VB term,
  and CFG on all noise channels; the conditional variance head is not guided.
  This is a declared teaching convention rather than exact original-code FID
  reproduction. Position encodings accept compatible rectangular token grids
  for separate position tests; the main evaluation protocol stays 256px.
- **SiT:** baseline versus REPA uses the same latent space. Compare uniform
  time with `--time-sampling logit_normal`; `--time-shift` changes the sampling
  distribution, not the linear path or velocity units. A 128px resolution
  experiment needs its own matching codec/data-size checkpoint, while using
  the same image IDs; report it separately from the 256px main comparison.
- **SR3:** compare regression, the original spatial-only model and a separately
  trained `--shuffle-condition` model. CDM supports `--no-class-condition` to
  isolate augmentation, followed by adding labels at the same augmentation
  setting. `--augmentation-level` at evaluation is bounded by the training
  range. For a generated-condition cascade pass `--low-checkpoint` from the
  128px conditional DDPM. Keep the real-condition evaluation as a separate run.
- **DMD2:** independently retrain with `--auxiliary-updates 1`, `--gan-weight 0`,
  or `--real-noised-inputs` to isolate its three increments. The default has
  five online auxiliary updates per student update and an online rollout.
- **iMF:** compare boundary reuse (`--no-auxiliary-head --conditioning adaln
  --guidance-max 1 --fixed-guidance-interval`) with the auxiliary-head,
  adjustable-guidance and condition-token increments, one change at a time.
  The model is trained from scratch; it reuses only the frozen image codec.
  Inference does not evaluate JVP or the auxiliary head. Original MeanFlow is
  the theoretical starting point, not an additional model-training obligation.

## 4. Monitoring and evaluation

Training saves `training.jsonl`, `training_curves.png`, `latest.pth`, and fixed
noise previews. `--sample-every` defaults to every epoch. `--eval-every 10`
adds KID on a fixed 2,020-image validation subset; zero disables either
monitor. Those RNG draws do not change the next training noise draw. Codec and
classifier lessons use reconstruction/category-specific monitoring instead.

The important diagnostics are target loss and noise/time bins, plus the
mechanism being learned: codec LPIPS/KL/scale, DiT's epsilon and VB terms,
REPA alignment, CD residuals, DMD2's fake-score error and update magnitude,
and iMF's unweighted induced-velocity error and JVP magnitude. Loss scales
from different objectives are not model-quality rankings. DMD2's surrogate
is not a measured KL; reweighted iMF loss alone is not a convergence measure.

Post-training evaluation reports:

- **Clean FID and KID:** pinned `clean-fid==0.1.35`, its `clean` Inception
  features, rounded RGB uint8 images and its PIL bicubic resize. The local
  Gaussian-distance function uses SciPy 1.18's `sqrtm(A)` API because
  Clean-FID 0.1.35 still passes the removed `disp` argument; the formula
  and complex-roundoff convention are retained. KID uses 50
  subsets up to 1,000 examples. Its finite-sample estimate may be negative.
  These values do not share the old torchvision-feature protocol.
- **Feature precision/recall:** full 2048-dimensional features, three-neighbor
  manifold estimates, alongside the distribution scores.
- **Categories:** independent evaluator accuracy, per-class compliance, valid
  sample counts and within-class feature distances. Validate that evaluator
  on real held-out data first. Large pairwise distance alone is not diversity.
- **Cost:** actual per-image-equivalent network evaluations (including CFG
  branches), decoder/upstream/guidance-classifier counts, warmed batch
  throughput, and separately measured batch-one latency. VP guidance includes
  classifier input-gradient computation. Initial weight loading, feature
  extraction and image writing are outside sampling time.
- **SR:** real-condition PSNR/LPIPS, bicubic PSNR and observation consistency;
  generated-condition cascades have no invented paired PSNR. The optional
  clean evaluator separates upstream category errors from class changes in SR.
- **Images:** fixed grids, paired condition/output/reference panels, and nearest
  examples from a declared fixed training subset (`--nearest-examples`, default
  2,020). Feature proximity does not prove or disprove memorization.

Each setting writes `metrics.json`; the evaluation directory contains
`comparison.json` and a quality/cost plot. No script writes paper benchmark
numbers into these outputs. Standard post-training inference currently uses
FP32; BF16 is a training option, not an unrecorded inference optimization.

## 5. Implementation and validation boundaries

[The diffusion package](../../dl_utils/diffusion/) contains its own codec,
PatchGAN, U-Net, Transformer and mechanism helpers. It has no imports from the
GAN/VAE model-family packages. Generic EMA, filesystem and feature-distance
primitives are shared. There is no distributed training, compile pipeline,
custom kernel, experiment registry or automatic cloud launcher.

Format-4 checkpoints store parameters, EMA, optimizer state, RNG state,
data/algorithm contracts and codec/teacher identities. Resume starts at the
next epoch; if `--max-steps` intentionally stopped a partial epoch, that
partial epoch is not replayed. Old CelebA checkpoints are not compatible.
`latest.pth` is a recovery artifact; preserve named copies for final selection
and comparisons. Wall-time records include periodic monitoring, and are
separate from the warmed inference timings.

```bash
uv run --locked --no-sync pytest -q tests/test_diffusion_lessons.py
uv run --locked --no-sync ruff check dl_utils/diffusion genai/3.0_diffusion_model tests/test_diffusion_lessons.py
```

The existing repository policy keeps `tests/` local and gitignored. These
verification commands refer to the suite in this working checkout; a fresh
clone contains the runnable lessons but not that local test suite.

The tests exercise mathematical/gradient boundaries, split reproducibility,
all 18 training entry loops and checkpoint reconstruction, next-epoch resume,
post-training metric plumbing and real 256px/32px shape contracts. Tiny test
fixtures replace external perceptual/semantic weights explicitly. These checks
are **not Food-101 training or generation-quality results**. Full cloud training,
matched ablations and held-out quality evidence must still be produced by runs.
